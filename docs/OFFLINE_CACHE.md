# 播客离线缓存

在订阅详情中为该节目选择缓存数量：**不缓存 / 最新 5 集 / 最新 10 集 / 全部**。默认不缓存。数量针对 RSS/Atom 列表中可下载的普通单集音频，不包括未列出的历史单集、直播、HLS 播放列表、网盘和 NAS 文件。

点按「刷新缓存」会先更新订阅列表，再按所选数量补齐缺失音频，已有完整文件不重复下载。刷新订阅列表失败时保留已缓存文件。播放时有完整缓存则优先读本机；没缓存的单集仍需联网。选择「全部」前请确认移动流量和剩余空间。

## 客户端实现

- 两端共享 [C++17 缓存核心](<../apple/NativeCache/PodcastNativeCache.cpp>)：计算保留数量、检查完整文件、原子落盘、修剪超额文件。Android 用 JNI 接口；iPhone/iPad 通过 SwiftPM 的 C 桥接目标调用。
- 原生平台负责网络安全、秘密存储、播放、后台能力和界面；不依赖播客后端。下载到应用私有目录，使用不透明文件名；音频不进入系统备份，不用于转播。
- 下载中的临时文件不作为离线音源。来源凭据只授权同源；公开媒体 CDN 不接收订阅凭据。适用的 HTTPS/TLS 等来源约束不会因缓存被绕过。

## 验收

- 使用 [CMake 原生测试入口](<../android/app/src/main/cpp/CMakeLists.txt>)，验证数量策略、完整性与失败时原文件保留、仅删除缓存文件。
- 用可控 RSS 端点验证刷新前后 URL、请求次数和错误码；再用真机飞行模式检查已缓存播放、拖动、部分失败与空间不足。构建和测试不代表真实音源均可缓存。
