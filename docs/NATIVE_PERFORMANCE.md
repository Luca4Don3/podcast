# Android 原生路径与性能验收

## 实现边界

- 这里的 C/C++ 指 **客户端**：Android 现有 C11 批量音源扫描器与 C++17 JNI 桥；Android、iPhone、iPad 共用 [C++17 缓存核心](<../apple/NativeCache/PodcastNativeCache.cpp>)，负责数量策略、完整文件验证、原子落盘和裁剪。系统界面、媒体会话、权限、网络认证与解码继续走平台接口。不要求自建后端。
- 原生扫描按 UTF-16 计算偏移，每批最多回传 101 条非空行的跨度（多出的 1 条用于拒绝超 100 条的输入），扫描结果工作区为 505 个 32 位整数（2020 字节）。JVM 可能复制输入字符串；该数字不代表整个 App 内存占用。
- 仅批量导入时尝试加载原生库；一次 JNI 调用处理整批扫描。原生库不可用则走 Kotlin 扫描，不改变 HTTP(S) URL 校验、错误行号、去重和整批拒绝规则。仅靠语言迁移不能证明总耗电下降。

## 播放时钟

- 播放状态切换由 Media3 事件驱动。暂停、停播和直播不启动周期进度计时。
- 前台可见且正在播点播时，每秒更新进度；锁屏或界面不可见时跳过 UI 更新，只保留每 5 秒的进度检查点。按调度设计，后台正播点播从约每分钟 60 次应用进度计时降到约 12 次，未含状态切换和系统媒体事件。
- 切集、暂停、退出界面等机会额外保存进度；强杀进程以最近一次已落盘的检查点为准。

## 构建与验收

- Android 7.0 / API 24 起，精简变体保留 ARM 32/64 位与 x86 32/64 位。
- 构建需 Android NDK r28c（28.2.13676358）与 Android SDK CMake 3.22.1；Gradle 目标为 `:app:assembleCompact`。
- C11 扫描核心可用标准主机 CMake 独立测试，源码在 [原生构建入口](<../android/app/src/main/cpp/CMakeLists.txt>)。JVM 单测默认支持回退路径，也可使用 `-Ppodcast.testNativeLibDir=/path/to/host/shared/lib` 强制真实 JNI 路径；该目录放置按宿主 JDK 头文件编译的库，不能用 Android ELF 代跑。
- 设备验收需同一台机、同一合法音源与音量/网络条件，对照测试无播放闲置、前台点播、锁屏点播和直播。建议记录 CPU 时间、应用进程 PSS 和待机耗电；不能用包体或工作区大小替代设备数据。

## 1.2.4-compact 交付结果

[通用 APK](<../dist/android-native-1.2.4/podcast-app-1.2.4-universal-compact.apk>) 为 3,040,239 字节，较 1.2.3 增加 81,033 字节（含四架构、包内对齐与代码改动），仍比 1.2.2 调试通用包小 86.6%。单架构扫描库约 3.5–5.0 KB，APK 中不包含 libc++_shared。签名、四架构、APK/ELF 16 KiB 对齐通过。C/CTest 通过；JVM 单测在实际宿主 JNI 和 Kotlin 回退两种模式各通过 38 项。手机运行与电耗未实测。
