# Android 多屏适配

应用优先使用当前窗口的真实数据：可用宽高、密度、系统栏、显示切口、软键盘，以及 Jetpack WindowManager 给出的折叠铰链边界、遮挡、分隔与半开状态。旋转、折叠、分屏和窗口大小变化后会重新计算。

对于系统**没有**报告切口的少数已知型号，使用型号兜底：同时匹配 Google Play 官方设备目录中的 `Model`、`Device`，核对原生面板宽高比，而且只在应用独占整块原生屏幕、没有折叠铰链时启用。未列出的设备不生成假切口，完全依赖系统报告。

| 场景 | 适配方式 |
|---|---|
| 窄长直屏、折叠外屏 | 保留单栏和底部导航；窄窗仅显示当前导航项的文字，其他项仍有无障碍名称。 |
| 普通直屏 | 单栏内容、底部导航与迷你播放器。 |
| 宽窗、展开后无分隔的平板 | 根据可用宽高切换侧栏；播放器按父容器实测宽度决定是否双列，内容区限制最大阅读宽度。 |
| 竖铰链 | 避开铰链，在两侧分布内容和播放器；RTL 界面交换主次侧。 |
| 水平铰链、桌面姿态 | 内容留在上方、播放控制留在下方。多铰链或无法分区时回退到最大的连续安全区。 |
| 系统已报告刘海／挖孔 | 直接避开窗口Insets与安全区；型号兜底不参与，避免重复留白。 |
| 系统未报告切口的已核实型号 | 小米 8 系列按官方发布深度避让；realme C55 与荣耀 Magic6 Pro 使用保守顶部留白。旋转后留白随物理边缘移动；不会按品牌泛化。 |

型号兜底仅包含可核实的具体型号：小米 8／8 SE／透明探索版／屏幕指纹版／小米 8 青春版／Redmi K30 使用[小米开发者文档](<https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1608>)的原生尺寸与切口深度；realme C55 `RMX3710`/`REE2ADL1` 的 Mini Capsule 是[围绕普通挖孔的动画](<https://www.realme.com/global/realme-c55>)，因此使用普通居中挖孔的保守留白，不生成软件胶囊区域；HONOR Magic6 Pro `BVL-N49`/`BVL-AN16`/`HNBVL` 按[官方规格](<https://www.honor.com/cn/phones/honor-magic6-pro/spec/>)使用 1280×2800 的居中双孔留白，不能与 1264px 的非 Pro 型号混用。`Model` 与 `Device` 标识来自[Google Play 支持设备目录](<https://storage.googleapis.com/play_public/supported_devices.csv>)。

大字、窄窗、短横窗下，展开播放器支持纵向滚动；文字、时间和播放控件根据可用空间回流，播放按钮保留至少 48dp 触控目标。连续改变窗口时保留导航状态，不主动重启播放。

## 验收建议

- 分别在普通直屏、窄长外屏、宽屏和折叠展开上观察导航。播放时折叠／展开或转动，确认当前页和播放状态保留。
- 在模拟显示刘海、居中挖孔、双切口的设备上检查登录、导航和展开播放器，确认系统栏、切口与键盘不遮住主要操作。
- 在真实小米 8、realme C55、HONOR Magic6 Pro 上分别检查竖屏、两个横屏方向以及分屏；分屏时不应再应用整屏的型号留白。
- 大字体下检查文件音源、设置、播放器及放大后的触控区；折叠设备要分别检查竖铰链、桌面姿态、外屏及不同厂商系统。
- JVM 单测验证窗口、铰链和已知型号几何策略，不能替代真机视觉验收；厂商定制 ROM 的实际Insets行为仍以系统输出为准。
